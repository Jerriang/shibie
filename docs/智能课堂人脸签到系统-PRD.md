# 智能课堂人脸签到系统（成品级 PRD v1.0）

## 1. 产品定义
### 1.1 产品名称
智能课堂人脸签到系统

### 1.2 产品目标
面向高校/培训机构/企业课堂场景，建设一套**低成本、高准确率、可审计、可落地**的考勤系统，实现：
- 自动识别“谁来了、谁没来、谁迟到了”；
- 防止照片、视频回放、替签、重复刷脸等作弊；
- 教师端在 10 秒内完成整班考勤确认；
- 保留人工兜底能力，降低纯 AI 误判风险；
- 满足隐私合规并控制部署成本。

### 1.3 目标用户
- 学校管理员
- 教师
- 学生
- 教务/审计人员
- 系统运维人员

### 1.4 核心价值
- 替代手工点名，提升课堂效率；
- 降低代签/误签风险；
- 形成可追溯、可审计考勤链路；
- 降低长期人工管理成本。

---

## 2. 成品级范围
### 2.1 必须做（MVP+）
1. 人脸注册与模板管理
2. 课堂签到与实时识别
3. 活体检测（PAD）
4. 出勤/缺勤/迟到判定
5. 重复签到拦截
6. 教师人工复核台
7. 补签申请与审批
8. 考勤报表导出（Excel/CSV/PDF）
9. 全链路审计日志
10. 账号、权限与 RBAC
11. 弱网/断网容错与补传
12. 数据加密与权限隔离

### 2.2 不建议一期做
- 跨校区万人级实时联动
- 情绪分析、行为轨迹分析
- 完全自动且无人工兜底
- 纯手机前端、缺少后端安全体系的方案

## 3. 业务场景与流程
### 3.1 场景 A：课前签到
1. 教师发起签到任务；
2. 教室设备开启采集（摄像头/平板）；
3. 学生站到镜头前；
4. 系统执行：人脸检测 → 活体检测 → 人脸识别 → 去重判断；
5. 成功则记为“已到”；
6. 低置信度进入“待教师确认”；
7. 截止后自动生成缺勤名单。

### 3.2 场景 B：迟到
- 超过签到开始后 X 分钟仍可签到，但标记“迟到”；
- 教师可手工更正为“正常/请假/缺勤”。

### 3.3 场景 C：识别失败
- 允许二次识别；
- 连续失败走人工补签/教师确认流程。

### 3.4 场景 D：作弊攻击
- 照片攻击、视频回放、多人替签、重复排队刷脸；
- 系统必须拦截并记录异常事件；
- 识别与活体需分层设计：仅做人脸比对不足以抵御展示攻击，必须叠加 PAD 与受信采集链路。

## 4. 功能需求
### 4.1 用户与权限
**管理员**：组织架构、班级课程、设备教室、规则配置、全局报表、审计查看。  
**教师**：发起签到、查看实时名单、处理低置信度样本、审批补签、导出班级报表。  
**学生**：注册/更新人脸、查看签到结果与历史记录、发起补签申请。  
**审计/教务**：查看不可篡改日志、异常记录、人工修改轨迹。

### 4.2 人脸注册模块
**功能**
- 上传/采集 3~5 张标准人脸图；
- 自动质量检测（模糊/遮挡/过暗/姿态偏转）；
- 提取特征向量并存储模板；
- 支持重新注册与版本管理；
- 默认不暴露原图。

**规则**
- 每名学生仅一个主身份；
- 支持注销与重建；
- 注册时必须留存“明示告知+授权”记录。

**验收指标**
- 注册成功率 ≥ 98%；
- 坏图拦截率 ≥ 95%。

### 4.3 签到识别模块
**输入源**：教室视频流/平板前置/USB 摄像头。  
**处理链路**：检测 → 跟踪 → 质量评分 → 活体 → 特征提取 → 1:N 检索 → 去重 → 写库。  
**输出状态**：
- 已到
- 迟到
- 缺勤
- 待确认
- 识别失败
- 活体失败
- 重复签到
- 异常攻击

### 4.4 活体防作弊模块（核心）
**必须支持**
- 照片攻击拦截
- 视频回放攻击拦截
- 同人多次刷脸拦截
- 高风险样本进入人工审核池

**推荐策略**
- 首选被动活体（降低交互成本）；
- 辅助规则：
  - 帧间纹理变化
  - 屏幕反光/摩尔纹检测
  - 深度/姿态一致性
  - 人脸面积变化与轨迹合理性
  - 短时多帧投票
- 高风险场景下切换轻交互活体（点头/转头/随机动作）。

### 4.5 教师确认台
- 实时名单：已签到、待确认、未签到；
- 对低置信度样本一键确认/驳回；
- 展示抓拍图与底库参考图；
- 可标注请假、公假、设备故障并补录。

> 说明：成品系统必须具备人工兜底，教师确认台是降低误判事故的关键。

### 4.6 补签与申诉
- 学生提交：原因、材料、申请时间；
- 教师处理：通过/驳回/改签到状态；
- 所有改动必须留痕，保留“原始状态 + 修改人 + 修改时间”。

### 4.7 报表模块
**指标**：签到率、出勤率、迟到率、缺勤率、异常识别率、活体失败率、人工修正率。  
**导出**：Excel / CSV / PDF。

### 4.8 审计与日志
必须记录：
- 签到任务发起人、时间、设备；
- 识别成功/失败及活体失败原因码；
- 教师人工修改操作；
- 补签审批记录；
- 配置变更、登录、权限操作。

要求：
- 日志不可随意删除；
- 管理员不能无痕修改；
- 支持按课程/班级/学生/时间检索。

## 5. 非功能需求
### 5.1 准确率与时延目标
- Top-1 正确认出率 ≥ 99.0%（受控环境）；
- 活体攻击拦截率 ≥ 95%；
- 漏签率 ≤ 1%；
- 误签率 ≤ 0.1%；
- 教师人工复核占比 ≤ 5%；
- 单人识别耗时 ≤ 1 秒；
- 50 人班级签到完成 ≤ 2 分钟。

### 5.2 性能
- 支持 1~4 路教室视频并行；
- 单机可稳定支撑单教室；
- 后端支持多班级并发；
- 识别结果写库延迟 ≤ 500ms。

### 5.3 可用性
- 系统可用性 ≥ 99.5%；
- 摄像头断开自动告警；
- 断网本地缓存，联网后自动补传。

### 5.4 安全
- 全链路 HTTPS；
- JWT/Session 安全机制；
- RBAC 最小权限；
- 原图与模板分级存储；
- 敏感数据加密；
- 关键接口限流与防重放。

---

## 6. 合规要求（高优先）
### 6.1 合规能力清单
1. 明示告知（采集内容、目的、保存时长、访问范围、删除路径）；
2. 单独同意/授权记录；
3. 提供非人脸替代签到方式（教师确认/校园卡/二维码/补签）；
4. 支持人脸数据删除与注销；
5. 采集最小化与保留期限策略；
6. 脱敏展示与分权访问；
7. 敏感操作留痕与可追溯。

### 6.2 禁止事项
- 强制刷脸且无替代方案；
- 全量原始人脸明文存储；
- 任意导出全量人脸库；
- 未授权将课堂数据用于其他训练；
- 管理员静默删除记录。

## 7. 推荐架构（两层识别）
### 7.1 边缘端（教室侧）
- 摄像头采集
- 人脸检测
- 活体初筛
- 特征提取
- 本地缓存

### 7.2 中心服务端
- 身份检索（1:N）
- 签到状态入库
- 课程规则引擎
- 报表与管理后台
- 审计日志

**收益**：低网络依赖、快响应、隐私更友好、云算力成本更低。

## 8. 技术路线（低成本成品）
### 8.1 硬件建议
- 最低可用：普通笔记本/迷你主机 + 1080P USB 摄像头 + 教师网页端；
- 稳定版：教室平板/一体机 + 外接摄像头 + 边缘盒子（NUC 级）；
- 不建议：ESP32-CAM 级方案直接上生产。

### 8.2 软件栈建议
- 后端：FastAPI / Spring Boot
- 数据：PostgreSQL / MySQL + Redis
- 对象存储：MinIO / OSS
- 前端：React + TypeScript
- 识别：SCRFD/RetinaFace + ArcFace + FAISS
- 活体：被动活体模型 + 规则引擎

## 10. 关键算法与规则
### 10.1 识别判定（联合决策）
必须综合：
- 相似度阈值
- 活体分数
- 图像质量分
- 时间窗口去重
- 同班候选约束
- 多帧一致性投票

### 10.2 去重规则（示例）
- 同一学生 5 分钟内不重复记新签到；
- 同一帧多人场景防“一人撞多 ID”；
- 连续 3 帧一致再确认签到。

### 10.3 低置信度处理（示例）
- 高相似度 + 高活体：自动通过；
- 中等相似度 + 高活体：教师确认；
- 低活体：直接拒绝；
- 低质量：提示重试。

## 11. 风险与防护
### 11.1 业务风险
- 照片/视频代签
- 同人替多人刷脸
- 教师私改数据不留痕
- 签到后提前离场仍算全勤

### 11.2 技术风险
- 伪造签到请求
- 直接改库
- 重放历史抓拍
- 模板泄露
- 越权导出
- 测试环境绕过正式审核

### 11.3 防护策略
- 前后端签名校验 + 设备身份校验
- 防重放 token
- 活体 + 多帧融合
- 权限分层 + 最小授权
- 审计日志 + 敏感导出审批
- 学校版可选“双人审批删除/修改”

## 12. 分阶段落地与成本
### 12.1 极致低成本版
教师笔记本 + 普通摄像头，单教室单机运行，支持本地识别与缓存。

### 12.2 可商用试点版（推荐首期）
教室边缘设备 + 中心后端 + 教师后台，打通活体、防作弊、审计、补签闭环。

### 12.3 校级版
多教室并发、统一身份中心、多端接入、设备管理、容灾与合规体系。

> 建议路径：先做“可商用试点版”，再扩校级能力。

## 13. 验收标准
### 13.1 功能验收
- 可完成注册、签到、补签、导出、日志追踪；
- 可准确区分到课/缺勤/迟到；
- 可拦截重复签到；
- 可展示待确认名单。

### 13.2 安全验收
- 照片攻击通过率 < 5%；
- 视频回放攻击通过率 < 5%；
- 无权限用户不可查看人脸模板；
- 所有考勤修改可审计。

### 13.3 性能验收
- 单人识别 < 1 秒；
- 50 人班级 2 分钟内完成；
- 断网 30 分钟不丢数据。

### 13.4 合规验收
- 有告知与授权页面；
- 有非人脸替代签到路径；
- 有删除/注销机制；
- 有数据保留策略文档。

---

## 14. 产品目标句（建议对外版本）
打造一套面向课堂场景的成品级智能考勤系统，基于人脸识别与活体检测实现高准确率签到，并通过人工复核、补签流程、审计日志和隐私合规机制，保障系统在真实教学环境中的可靠落地。
